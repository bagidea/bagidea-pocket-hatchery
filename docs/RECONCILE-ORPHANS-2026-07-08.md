## Root cause (why these exist)
The pre-fix `mint_creature`/`breed` read the minted `asset_id` **back** after dispatching the
inline `mintasset` — but an inline `.send()` runs *after* the action returns, so the read-back
returned the **previous** mint's id. Result: `creatures` rows bound to the wrong asset, leaving
some real NFTs with no game row (**orphans**) and some game rows with no NFT (**ghosts**). This is
exactly what the `predict_asset_id` fix (staged, `docs/PREDICT-ASSETID-FIX.md`) removes going
forward. These 5 records are the residue from the buggy runs — all generated by dev/debug hatches
on testnet, not by real users.
