## Issue #1 — Ghost fix: need `syncowner` action (BLOCKED — configv2 source LOST)

**Problem:** 3 creatures have `creatures.owner` ≠ real AA owner. No existing action can fix this.
`burncreature` requires auth of the stale owner (not admin), and it burns the real NFT — disqualified.

| asset_id | creatures.owner | real AA owner |
|---|---|---|
| 1099603751699 | officewax123 | waxwingsuper |
| 1099603751700 | waxwingsuper | officewax123 |
| 1099603751707 | waxwingsuper | officewax123 |

**Root cause:** Pure P2P user↔user transfers. AA `transfer` only notifies `from`+`to` — never
`phgamecreatr`. Even configv3's `on_assets_transfer` handler can't catch this (contract is not a
party). The only permanent fix is a custody/deposit model. For now, an admin `syncowner` action +
off-chain AA-transfer watcher is the pragmatic path.

**Fix:** Add `syncowner(asset_ids, new_owner)` action — admin-only (`require_auth(get_self())`),
touches ONLY `creatures` table. Patch diff ready: `_recon/PATCH-syncowner.diff` (verified applies
clean against configv3 source).

**Blocker:** The on-disk source is **configv3** (decay economy). The **configv2** source that
produced `0a21adc3` was edited in-place — **no backup, no git**. Two paths:

| Path | What | Risk |
|---|---|---|
| **(A) Reconstruct configv2** | hand-revert decay diff → compile → verify hash == `0a21adc3` → add syncowner → deploy | High effort, need byte-proof |
| **(B) Ship configv3** | deploy current source (compiles clean, wasm `d8733d5d…`) → lands decay economy + syncowner | Ships entire Feed-v2 (see Issue #2) |

**Recommendation:** Path (B) — kill two birds, but ONLY after CEO approves Feed-v2 numbers (Issue #2).

## Issue #3 — Template mismatch: 662889/662906 creatures earn 0 on harvest

**Problem:** `speciescfg` table is keyed by `template_id`. Live speciescfg has:
- 662976 (common), 662977 (uncommon), 662978 (rare)

But actual creature rows use templates:
- **662889** (common?), **662906** (uncommon?), **662977** (uncommon)

Only **662977** overlaps → creatures with template 662889 or 662906 find NO `speciescfg` row →
`harvest` skips them (earn 0). Their NFT immutable data still has valid genes/art — it's a
**config data bug**, not a contract logic bug.

**Fix options:**
- **(A)** `setspecies` for 662889 + 662906 with correct egg_type + yield curve
- **(B)** `rmspecies` the unused 662976/662978 and re-key to 662889/662906
- **(C)** Burn + re-mint affected creatures under correct templates (destructive, last resort)

**Impact:** All non-662977 creatures earn nothing on harvest. This is a live bug affecting real
testnet creatures.
